# 04. Bookmarks and destinations

[Tutorial path](README.md) · [Previous: graphics](03-graphics.md) · [Next: links](05-links.md)

## Goal and prerequisites

Create three pages, a hierarchical bookmark outline and named destinations. The [first document](01-first-document.md) and [pages and text](02-pages-and-text.md) tutorials already explain resources, streams and the page tree. Install dependencies with `composer install`; PHP 8.3 or later and the extensions listed by Composer are required.

The complete script is [examples/navigation.php](https://github.com/PDFToolkit/pdf/blob/v0.5.4/examples/navigation.php). Each step is commented; it runs independently and does not use files generated by other tutorials.

## Run and inspect

From the root of a core checkout:

```sh
php examples/navigation.php
# Custom destination, in an existing directory:
php examples/navigation.php navigation-demo.pdf
```

Without an argument, the file is `examples/navigation.pdf`. Open the PDF in a reader with a bookmarks panel. The result contains three chapters. The bookmark “Comprendre la navigation” has three children; clicking the second displays the second chapter at 100% zoom. The others fit the entire page. The catalog requests that the panel be opened, but the reader decides how to honor that preference.

![Preview of the navigation tutorial's first page](../../tutorials/previews/navigation.png)

The preview is an image of the page; bookmarks belong to the PDF's interactive structure, outside its drawing.

## Read the construction

1. **Pages and outlines are separate trees.** `PageTreeNode::addKid()` determines reading order. `OutlineDictionary::addItem()` and `OutlineItem::addItem()` build an independent outline: its editorial hierarchy can differ from the page hierarchy.
2. **A destination targets a Page object.** `new Fit($page)` builds the array `[page-reference /Fit]`. The page number displayed by a reader follows from the page's position in the tree; it is not the identifier used by this destination.
3. **`XYZ` specifies the view.** The script passes three `NumericType` objects with values 0, 842 and 1: the target is the top edge of the page and zoom is 1, or 100%. A PHP `null` parameter becomes a PDF `null` object, asking the reader to preserve that parameter from the current view. For zoom, the specification also gives value 0 that meaning.
4. **Outline links are derived.** Outline objects produce `/Parent`, `/Prev`, `/Next`, `/First`, `/Last` and `/Count` from their attachments. Titles are `TextString` values: they can contain accented characters here, independently of the encoding used for text drawn with Helvetica.
5. **Named destinations provide stable keys.** `NameTree` associates `chapitre-1`, `chapitre-2` and `chapitre-3` with explicit destinations. Its keys are byte strings represented by `LiteralString` and sorted by the tree object. `NameDictionary` exposes it under `/Dests`, and the catalog entry `Names` exposes that under `/Names`.
6. **The catalog connects everything.** `new Outlines(new IndirectReference($outline))` satisfies this entry's indirect-reference requirement. `PageMode::UseOutlines` defines the interface preference; `OpenAction($firstPage)` defines the initial view.

The script publishes named destinations to show their construction. Its bookmarks use `Fit` and `XYZ` directly; the presence of a name tree does not automatically turn these targets into named destinations.

| --- | --- | --- |

| `NameTree`, `NameTreeEntry` | Associate strings with values | §7.9.6 |

## Variations and limitations

Pass `expanded: false` to the constructor of an `OutlineItem` with children to present it initially collapsed. Replace `Fit` with `XYZ` to specify the view; other classes in namespace `PDF\Document\Destinations` represent the specification's fitting modes.

To activate a named destination from an annotation, use `DestEntry(new LiteralString('chapitre-2'))` in a document whose catalog publishes that key under `/Names /Dests`. The [next tutorial](05-links.md) shows annotation construction and the variation using an explicit destination.

The outline does not draw a visible table of contents on the pages. A printable table of contents needs text operators and, optionally, link annotations. Each reader interprets zoom settings and the request to open the panel.
